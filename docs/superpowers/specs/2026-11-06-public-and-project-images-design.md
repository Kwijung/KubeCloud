# 공용 이미지와 프로젝트 이미지 설계

작성일: 2026-11-06

## 1. 목표

이미지를 두 범위로 나눈다.

- **공용 이미지**: 관리자가 등록하고 모든 프로젝트가 읽기 전용으로 쓴다 (Ubuntu, Debian, CirrOS 같은 배포판 클라우드 이미지).
- **프로젝트 이미지**: 프로젝트 멤버가 등록하고 그 프로젝트에서만 보인다.

AWS AMI(공개 AMI / 내 AMI)와 GCP(공개 이미지 / 커스텀 이미지)와 같은 모델이다. 지금은 프로젝트마다 같은 배포판 이미지를 따로 등록해야 해서, 같은 URL이 프로젝트 수만큼 중복된다.

## 2. 범위

### 포함

- 이미지에 범위(`public` / `project`) 추가
- 공용 이미지 등록·삭제 API (관리자용 경로)
- 프로젝트 이미지 목록과 공용 이미지 목록을 함께 돌려주는 조회
- VM 생성 시 프로젝트 이미지와 공용 이미지 모두 선택 가능
- 공용 이미지 삭제 가드: 어느 프로젝트에서든 VM이 쓰고 있으면 거부
- 콘솔: 이미지 화면을 "프로젝트 이미지"와 "공용 이미지(읽기 전용)"로 나누고, VM 생성의 이미지 선택도 두 묶음으로 표시

### 제외

- 공용 이미지 등록 권한 검사: 로그인과 역할([계정과 역할 설계](2026-11-06-accounts-and-roles-design.md))이 들어오기 전까지 관리자 경로는 인증 없이 열려 있다. 역할이 생기면 `admin`만 호출하도록 막는다.
- 이미지 미리 가져오기(golden PVC)와 그에 따른 `Importing` 상태: 별도 작업이다. 이미지는 지금처럼 등록 즉시 `Ready`이고, 디스크는 VM 생성 때 URL에서 받는다.
- 프로젝트 이미지를 공용으로 승격하는 기능

## 3. 데이터 모델

`images` 테이블:

| 컬럼 | 변경 |
|---|---|
| `project_id` | NULL 허용. 공용 이미지는 NULL |
| `scope` | 새 컬럼, `'public'` 또는 `'project'`. `CHECK ((scope = 'public') = (project_id IS NULL))` |
| `virtual_size_bytes` | 그대로 (qcow2 헤더에서 읽은 크기, 모르면 NULL) |

- 이미지 ID: 프로젝트 이미지는 지금처럼 `<project>-<name>`, 공용 이미지는 `public-<name>`.
- 이름 중복 검사: 프로젝트 이미지는 같은 프로젝트 안에서, 공용 이미지는 공용 이미지끼리. 프로젝트 이미지와 공용 이미지의 이름은 겹쳐도 된다 (목록에서 범위로 구분).
- 기존 데이터: 지금 있는 이미지는 모두 `scope = 'project'`로 둔다. 시드 데이터의 CirrOS는 공용 이미지로 옮긴다 (VM이 참조하므로 ID는 유지하고 `project_id`를 NULL로 바꾼다).

## 4. API

| 메서드·경로 | 동작 |
|---|---|
| `GET /api/v1/projects/{p}/images` | 그 프로젝트의 프로젝트 이미지와 모든 공용 이미지. 각 항목에 `scope` |
| `POST /api/v1/projects/{p}/images` | 프로젝트 이미지 등록 (지금과 같음) |
| `DELETE /api/v1/projects/{p}/images/{id}` | 프로젝트 이미지 삭제. 공용 이미지 ID면 404 |
| `GET /api/v1/admin/images` | 공용 이미지 목록과 이미지별 사용 VM 수(전체 프로젝트) |
| `POST /api/v1/admin/images` | 공용 이미지 등록. 검증·크기 읽기는 프로젝트 이미지와 같음 |
| `DELETE /api/v1/admin/images/{id}` | 공용 이미지 삭제. 사용 중이면 409 `IMAGE_IN_USE` |

VM 생성(`POST /projects/{p}/vms`)은 `imageId`가 그 프로젝트의 이미지이거나 공용 이미지이면 받는다. 다른 프로젝트의 프로젝트 이미지면 지금처럼 400 `INVALID_IMAGE`.

## 5. 콘솔

- 이미지 화면: 위에 프로젝트 이미지 표와 등록 폼, 아래에 공용 이미지 표(읽기 전용, "이 프로젝트에서 사용" 열).
- VM 생성: 이미지 카드를 "공용 이미지 · 관리자가 제공"과 "프로젝트 이미지" 두 묶음으로 표시. 디스크가 작은 사양을 막는 규칙은 범위와 관계없이 같다.
- 관리자 화면의 공용 이미지 관리는 로그인과 역할이 들어온 뒤 관리자 모드 메뉴에 붙인다. 그 전에는 API로만 등록한다.

## 6. 테스트

- 저장소: 공용 이미지 등록·중복·삭제 가드, 프로젝트 목록에 공용 이미지 포함, 다른 프로젝트의 프로젝트 이미지로 VM 생성 거부, 공용 이미지로 VM 생성 허용, 기존 CirrOS 이전 후 VM 참조 유지.
- 라우터: 관리자 경로의 상태 코드와 오류 코드, 프로젝트 경로에서 공용 이미지 삭제 시 404.
